# Prototype Instructions

Run the local server yourself and open the preview in the in-app browser. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

## DeepSeeker direction

- Keep the approved centered black hero with the rainbow whale, horizontal light beam, platform selector, download actions, and a large real product screenshot.
- Keep the approved lower-page order: three setup steps, product capabilities, MIT/open-source proof, FAQ, footer.
- Motion should borrow the pacing of the official DeepSeek Harness site while using DeepSeeker's own rainbow-whale language. Prefer subtle continuous canvas motion, scroll reveals, product-window parallax, and responsive reduced-motion fallbacks.
- Public copy stays short and conversational in Chinese and English. Avoid generic SaaS marketing copy.
